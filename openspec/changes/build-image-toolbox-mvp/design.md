# Design

## Context

全新纯前端项目，动机见 proposal.md - Why。核心约束：不依赖任何后端与 API key，全部功能开箱即用；图片绝不离开浏览器；算法要可讲解（面试会问抠图怎么做的）。

## Goals / Non-Goals

**Goals:**

- 清晰的纯前端分层：`src/views/`（工具页）、`src/lib/`（纯函数图像处理算法）、`src/components/`（通用组件）
- 图像算法与 UI 解耦：lib 内为纯 Canvas 函数，可单测、可复用到 exe 壳
- 首屏即可用，无配置步骤

**Non-Goals:**

- 不做 AI 语义抠图（复杂背景人像分割）——首版只做纯色底抠图，复杂背景明确提示局限
- 不做批量处理与历史记录
- 本阶段不做 exe / APK 打包

## Decisions

1. **纯前端无后端**：Canvas 2D 足以覆盖全部需求，零部署成本（静态托管即可），隐私是天然卖点。备选后端 Sharp 处理更快但违背「零上传」定位。
2. **纯色抠图用色度距离 + 边缘羽化**：采样顶部边缘估计背景色（底部两角常被肩膀占据），逐像素计算与背景色的 RGB 距离生成 alpha 遮罩，阈值内全透明、过渡带线性羽化，再做前景色去污染（减去背景色贡献）。O(n) 单遍扫描，1200 万像素以内流畅。备选 flood-fill 只适合完全连通纯色，对渐变背景鲁棒性差；AI 分割模型（如 imgly）需下载 40MB+ 模型，国内网络不稳，列为后续增强。
3. **压缩用 canvas.toBlob 质量参数 + 二分逼近目标体积**：用户给定目标 KB 时二分质量参数（最多 8 轮）逼近，讲得出算法。备选直接固定质量简单但满足不了「压缩到 200KB 以内」这类报名网站硬需求。
4. **裁剪交互自绘 overlay**：在预览 Canvas 上叠 div 选区，8 向控制点 + 比例锁定，不引裁剪库，原理可讲清。备选 cropperjs 成熟但黑盒。
5. **排版按 300DPI 毫米换算**：六寸 152×102mm → 1800×1200px，间距 2mm，行列数向下取整，纯算术。

## Risks / Trade-offs

- [纯色抠图对渐变/阴影背景效果差] → 背景方差检测超阈值时明确提示；规格已写明不假装成功
- [大图（>4000 万像素）逐像素处理卡顿] → 处理时先缩到最长边 4096 的工作副本，导出按工作副本尺寸；提示用户
- [HEIC 等格式浏览器不支持] → 载入时校验 MIME，明确提示支持 JPG/PNG/WebP

## Migration Plan

全新项目无迁移。部署：`npm run build` 产出纯静态 `dist/`，任意静态托管（GitHub Pages / Nginx）即可上线；无服务端状态，回滚即回退静态文件。
